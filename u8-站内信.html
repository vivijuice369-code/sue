需求背景说明

✕

用户对存款、提现、活动、账户安全等状态变化，此前只能被动找客服咨询或自行查询，平台缺少统一及时的触达渠道，客服也因重复咨询承担了不少人力成本。

「消息通知」在系统层面预置「资金」「VIP」「安全」等通知规则（「活动通知」对接独立的「活动后台」）。管理员配置好多语言内容并开启后，用户触发对应行为时，系统自动生成并推送通知，无需人工发送——既提升用户体验与安全感，也减少客服重复答疑，并为后续扩展预留统一入口。

需要特别说明：「平台通知」是原有公告功能，本次不调整；「消息通知」是新增的独立功能，两者同在「消息中心」但目的不同——前者偏公告发布，子标签只做展示切换；后者偏业务触达，子标签按类型真实筛选，互不影响。

另外，自动通知只能覆盖系统预置的固定场景，无法满足对个别用户或特定人群一次性、灵活触达的需求（如给大R发专属关怀信）。因此新增「站内信」：可针对会员ID、VIP等级+标签筛选的人群、或全部会员手动编写发送，展示在「个人消息」子分类，复用已读、红点与批量操作机制，内容完全由运营主导。

📋「消息通知」功能规则说明

0. 与「平台通知」相互独立。后者为原有功能、本次未调整，关系见「背景说明」。其红点与未读标记沿用原实现、本次不改造，原型中为静态展示，点开不会消减，属预期表现。

1. 按类型分类展示。分「个人消息 / 资金 / 活动 / VIP / 安全」；资金、VIP、安全由本后台配置，活动来自「活动后台」（见「流程图」），个人消息即「站内信」（见右侧面板），展示体验一致。

2. 只看得到后台已开启的通知，关闭后不再收到。

3. 触发对应行为会自动收到通知，如存款、提现、参与活动、VIP升降级、领取礼金、改密码、非常用设备登录等，无需人工发送；原型列表为演示数据，实际以真实触发为准。

4. 未读消息有红点数字提示，点开详情返回后数字会减少。

5. 时间按本地时区展示。以后台实际发送 / 触发时间为准，按设备时区换算；不同时区看到的时间不同、但为同一时刻，平台通知同理。

6. 显示语言有兜底保护。正常展示自己语言的完整内容；仅当后台数据异常缺失时，才依次兜底英文、中文。

7. 支持批量操作，仅作用于「消息通知」。有未读时只显示「全部已读」，全部已读后才变「全部删除」，均需二次确认；详情页也可单条删除，不影响平台通知与后台配置。

📋「站内信」功能规则说明

1. 站内信属于「消息通知 - 个人消息」。不同于系统自动触发的通知，它由运营针对会员ID、定制会员或全部会员主动发送，入口相同，仅子标签不同。

2. 只有发给「我」的信才会收到，仅匹配当前账号的信件会出现在「个人消息」里。

3. 每条信件都带有署名，由运营按语种分别配置（如运营/风控/客服团队）；自动通知署名固定为「系统通知」，这是两者的主要区别。

4. 多语言展示、未读红点、已读、批量与单条删除等交互，与其他类型完全一致，详见左侧面板。

5. 定时发送的信件上线后由后端到点下发，用户端此前看不到；本原型为便于演示，保存后两种方式均直接显示，不代表真实定时效果。

📋「消息通知」功能规则说明

✕

0. 与「平台通知」相互独立，后者为原有功能不作调整；本节仅针对「消息通知」，关系见「背景说明」；

1. 类型与时机为系统预置，不可新增删除，仅可编辑内容；「活动通知」已移交「活动后台」，此处保留资金、VIP、安全通知，流转见「流程图」；

2. 标题、内容需配置中文及英/越/韩/俄四语种，全部完整才可保存；标题限50字、内容限1000字，超出无法继续输入；

3. 功能发布后默认全部「关闭」，需运营配置完内容后手动开启，避免误触达用户；

4. 状态只能在「编辑」页切换，列表页仅展示文字（绿色开启 / 红色关闭，不可点击），防止误触；开启后实时同步至用户端；

5. 内容支持链接、图片与变量占位符。编辑器上方按通知时机展示「可用变量」按钮（如「提款失败」对应「金额」「失败原因」），点击即插入；占位符替换由后端实现，用户看到的是替换后的真实内容；

6. 语种兜底（仅异常场景）：正常已强制5语种完整；若数据异常缺失，依次兜底英文、中文，避免空白；

7. 「操作人」为最近一次保存该条通知的账号。预置数据未被配置过显示「未配置」，保存后写入当前账号并更新「更新时间」；

8. 用户端时间按设备时区自动换算，此处均为后台时区，不同时区看到的时间不同但为同一时刻；

9. 用户端「全部已读 / 全部删除 / 单条删除」仅作用于「消息通知」，不影响平台通知与后台配置；全部已读后按钮才变为「全部删除」，两者均需二次确认；后台站内信「删除」同样需确认。

0. 站内信与「自动通知」相互独立。自动通知由用户行为触发系统生成；站内信由运营针对会员ID / 定制会员 / 全部会员主动创建发送，需逐条编写；

1. 发送对象三选一：「会员ID」精确指定（支持多个，可Excel导入，重复自动过滤）；「定制会员」用 VIP等级 + 会员标签筛选，两者均可多选、可搭配，按并集圈选，命中多条件只发一封；或「全部会员」；

2. 会员ID超过2个时列表默认折叠，显示「前2个ID 等 N 位会员」+「查看」按钮，点击展开（超高可滚动）并变为「收起」；定制会员、全部会员不折叠；

3. 标题、内容、署名均需配置中文及英/越/韩/俄四语种，全部完整才可保存，规则与自动通知一致；

4. 署名按语种分别配置、不可为空、限20字，标签随语种变化；中文默认「运营团队」，其余需自填。快捷按钮固定显示中文，点击后按当前语种填入对应翻译，也可手动输入；

5. 发送方式分「立即发送」与「定时发送」，后者需指定时间、到点自动发出；本原型为便于演示，保存后两种方式均直接同步到用户端，真实环境需到点才触达；

6. 已发送记录不可编辑，操作列只保留「删除」；未发出的记录可「编辑」或「删除」。删除已发送记录仅从后台移除，用户端内容不会被撤回；删除未发出的记录则取消发送；

7. 列表默认按「创建时间」倒序，最新排最前；点击左侧置顶按钮可固定到顶部，置顶记录不参与倒序、始终居首；

8. 「操作人」为最近一次保存该信件的账号，保存后自动写入；用户端时间按设备时区自动换算，此处均为后台时区；

9. 用户在「消息通知 - 个人消息」中查看收到的站内信，未读红点、已读、删除等交互与其他类型统一。
