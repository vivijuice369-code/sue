需求背景说明

✕

目前用户对存款、提现、活动进度、账户安全等关键节点的状态变化，只能被动地找客服咨询或自己反复查询，平台缺少一个统一、及时的消息触达渠道，客服端也因为大量重复咨询而承担了不小的人力成本。

「消息通知」功能希望在系统层面预置「资金通知」「活动通知」「安全通知」三大类、覆盖常见业务节点的通知规则。管理员只需要在后台把每条通知的中文及英/越/韩/俄多语言内容配置好、并开启状态，后续只要用户在平台上触发了对应的业务行为，系统就会自动生成并推送对应的通知，不需要人工逐条发送。

这样一方面能让用户更及时地了解自己账户和活动的实时状态，提升体验和安全感；另一方面也能减少客服重复答疑的工作量，同时为后续拓展更多通知类型预留了统一的配置入口。

需要特别说明的是：「平台通知」是原有的公告功能（全部公告/新人专属/系统公告/活动公告），本次不做调整；「消息通知」是本次新增的独立功能。两者虽然都在「消息中心」里，但设计目的不同——「平台通知」偏运营公告发布，子标签只做展示态切换；「消息通知」偏业务事件触达，子标签会按类型真实筛选内容。这两套逻辑分开设计、互不影响。

另外，「消息通知」自动触发的通知只能覆盖系统预置的固定场景（存款、提现、VIP变动、安全事件等），无法满足运营针对个别用户或特定人群做一次性、灵活内容触达的需求（比如给某几个大R会员发一封专属关怀信，或者给新注册但还没首充的用户群体推一条提醒）。因此在「消息通知」的基础上，又新增了「站内信」能力：运营可以在后台针对指定的会员ID、或按VIP等级 + 会员标签圈选的人群，手动编写并发送一条消息，内容展示在用户「消息通知」下新增的「个人消息」子分类里，与自动通知共用同一套已读、红点、批量操作机制，但内容完全由运营主导，不依赖系统预置的触发条件。

📋「消息通知」功能规则说明

0. 与「平台通知」是两套独立逻辑。「平台通知」为原有功能，本次未做调整；以下规则仅针对「消息通知」，两者关系详见「背景说明」。

1. 按类型分类展示。分为「个人消息」「资金」「活动」「VIP」「安全」几类；资金、VIP、安全类型由「消息通知」后台配置，活动类型的内容来自「活动后台」独立配置（详见「流程图」），个人消息即运营在后台发送的「站内信」（详见右侧「站内信」说明面板），展示体验一致，用户无感知差异。

2. 只看得到后台已开启的通知。后台开启后才会出现在「消息通知」里，关闭后不再收到。

3. 触发对应行为会自动收到通知。比如完成存款、提现、参与活动、VIP升降级、领取礼金、修改密码、非常用设备登录等，只要通知已开启就会自动推送，不需要人工发送；本原型中的消息列表为演示数据，实际以用户真实触发的业务行为为准。

4. 未读消息有红点数字提示，点开详情返回列表后，对应红点数字会减少。

5. 显示语言有兜底保护。正常都会看到自己语言的完整内容；仅当后台数据异常导致缺失时，才会依次兜底展示英文、中文，避免看到空白。

6. 支持批量操作，仅作用于「消息通知」。可一键「全部已读」或「全部删除」，详情页也可单独删除；不会影响「平台通知」或后台配置。

📋「站内信」功能规则说明

1. 站内信属于「消息通知 - 个人消息」。与其他系统自动触发的通知不同，站内信是运营针对指定会员ID、定制会员（VIP等级+会员标签组合）或全部会员主动发送的消息，展示在同一个「消息通知」入口下，只是子标签换成了「个人消息」。

2. 只有发给「我」的信才会收到。运营发送时指定的是会员ID或VIP等级 + 会员标签，只有匹配到当前账号的信件，才会出现在这个用户的「个人消息」里。

3. 内容按当前语言展示，运营配置时已同步准备好中/英/越/韩/俄五个语种，用户会看到自己所用语言对应的版本。

4. 每条信件都带有署名，默认展示「运营团队」，运营也可以改成其他署名（如「客户关怀中心」），方便用户知道是谁发的。

5. 未读红点、已读、删除等交互和其他类型通知完全一致，点开详情返回后红点数字减少，也支持「全部已读」「全部删除」和单条删除，只影响自己账号收到的信件。

6. 定时发送的信件，会在运营设定的时间点准时出现在用户的「个人消息」里，用户端不会提前看到。

📋「消息通知」功能规则说明

✕

0. 与「平台通知」是两套独立逻辑，「平台通知」为原有功能，本次不作调整；以下规则仅针对「消息通知」，两者关系详见「背景说明」；

1. 通知类型与通知时机为系统预置，不支持新增或删除，仅可编辑内容；「活动通知」已移交「活动后台」独立配置，此处保留资金通知、VIP通知与安全通知，配置流转详见「流程图」；

2. 每条通知需配置中文标题与通知内容，同时配置英语 / 越南语 / 韩语 / 俄语四个语种，全部配置完整才可保存；标题限50字、内容限1000字，输入框右侧实时显示已输入字数，超出上限无法继续输入；

3. 功能发布后默认全部「关闭」，需运营逐条配置好内容后手动开启，避免内容未配置齐全就误触达用户；

4. 状态开关只能在「编辑」页面切换，列表页仅展示状态文字（绿色「开启」/ 红色「关闭」，不可点击），避免误触导致内容未配置完就被打开；开启后会实时同步到用户端；

5. 通知内容支持链接、图片与变量占位符。富文本编辑器支持插入超链接、图片；也可手动输入变量占位符（如「{金额}」「{失败原因}」「{设备名称}」，具体可用哪些以触发时机为准，暂无一键插入按钮）。占位符与实际业务数据的映射、替换逻辑由开发在后端实现——用户最终看到的是替换后的真实内容，不会看到 {} 本身；

6. 语种兜底（仅用于异常场景，非正常保存路径）：正常保存已强制要求5个语种全部完整；万一出现数据异常导致某语种缺失，会优先兜底展示英文，其次中文，避免用户看到空白；

7. 用户端「全部已读」「全部删除」「单条删除」仅作用于「消息通知」，不影响「平台通知」，也不会改变后台配置数据。

0. 站内信与「自动通知」是两套独立逻辑。「自动通知」由用户触发业务行为后系统自动生成；「站内信」是运营针对指定会员ID / 定制会员 / 全部会员主动创建发送的消息，需要运营逐条编写内容，系统不会自动生成；

1. 发送对象支持三种方式：按「会员ID」精确指定（支持多个ID，也支持Excel批量导入ID）；按「定制会员」用「VIP等级」+「会员标签」两个下拉框组合筛选，两者均支持多选、可以组合搭配（例如「VIP3、VIP4」+「千元用户」），系统按并集圈出符合任意条件的会员，若某会员同时满足多个条件也只会收到一封信，不会重复发送；或选择「全部会员」发送给平台当前全部会员；

2. 信件标题、信件内容都需要配置中文及英语 / 越南语 / 韩语 / 俄语四个语种，全部配置完整才可保存，规则与「自动通知」一致；

3. 信件署名默认展示「运营团队」，可自行修改为其他署名，用于告知用户这封信是谁发的；

4. 发送方式分「立即发送」和「定时发送」，选择「定时发送」需指定具体发送时间，到点后系统自动发出；

5. 已发送的记录不可再编辑，操作列只保留「删除」；「定时中」等尚未发出的记录可以「编辑」或「删除」；

6. 列表支持「置顶」，点击每条记录左侧的置顶按钮可以把它固定到列表最前面，方便运营快速找到重要信件；

7. 用户在用户端「消息通知 - 个人消息」里看到的就是运营发给他的站内信，未读红点、已读、删除等交互与「消息通知」下其他类型统一，互不冲突。
